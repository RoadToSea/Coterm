## 基座与驱动的边界

- 基座负责驱动生命周期、实例路由、前端挂载、来源识别、审批、公共交互、操作记录和 MCP Bridge。
- Serial 驱动负责串口配置与连接、文本和 HEX 收发、控制线、输出缓冲及命令队列；具体设备协议由独立驱动实现。
- 前端仅通过基座 API 调用驱动；实例级调用由宿主绑定实例，MCP 对外使用公共实例名称，UUID 只在内部路由。
- 驱动单独注册 MCP descriptor 和内部操作映射，不能因业务操作存在就自动向 Agent 开放。串口人工单次写入和控制线接口不注册为 MCP 工具。
- Agent 提交经过宿主审批，Bypass 或放行只跳过提交审批；秘密交互、协议认证和交付不确定性仍按运行时规则处理。

## 串口界面

实例通过 `mode:stream|shell` 显式选择数据解释方式，默认 stream；终端 / UART 是独立的显示视图。两种模式都提供后端 `read_lines`，只有 Shell 支持 `read_selected_lines` 和 `read_dialogue_pairs`。模式及完整字面提示符可在创建配置中保存，也可断开后通过 `serial.configure` 修改当前实例。Shell 每条命令各自等待提示符，超时停止余项；匹配仅代表观测到边界，串口的 stderr 合并至 stdout，退出码保持 null。MCP 移除游标读取工具；前端内部回放、缺口恢复和 HEX 视图继续使用游标，不把维护责任交给 Agent。能力、容量和限制以 [接口设计](../../drivers/driver-serial/docs/interfaces.md) 为准。

新建实例通过驱动级只读操作 `serial.driver_info` 获取本机 `ports`，不依赖已有实例。基座在配置页调用前启动驱动并完成握手；每次点击或键盘展开端口下拉框时重新枚举，保留仍存在的选择，不再提供独立刷新按钮。在途查询合并重复触发；支持原生 `showPicker` 的宿主读取新列表后再展开，避免弹出的菜单保留旧快照。只有成功返回空数组时显示「未检测到串口」；启动 / 查询失败、旧后端缺失 `ports` 等情况显示错误，再次点击下拉框可重试，加载中或无有效端口时不能提交。此过程不打开串口、不修改 DTR / RTS，也不发送设备数据。

界面与配置由驱动前端自行管理。终端保留原始按键语义；UART 使用 Enter 单次发送、Shift+Enter 换行，输入法组合期间 Enter 不发送。配置平铺，在接收区上方展开，不改变接收区与发送栏尺寸。断开后可编辑本地通信草稿，在下次人工连接前通过 `serial.configure` 应用，成功后才调用 `serial.connect`；固定端口不显示为可修改项，不保留应用按钮或端口列表。顶栏连接按钮同时表示状态：连接时绿色，断开时灰色。

UART 接收 ASCII / HEX、暂停、清空和保存放在快捷栏。配置右侧点击调整快捷栏后，控件围绕自身中心小幅快速晃动，直接拖动排序并显示插入位置；拖动时接收区下方显示垃圾桶，投放后移除。原显隐复选框列表由紧凑提示、恢复默认和完成操作替代，移除后可单项加回。键盘可用 Alt + 左右方向键排序、Delete / Backspace 移除。调整期间抑制控件原业务动作，取消拖动不改变布局，关闭调整恢复正常操作；减少动画设置下禁用晃动。只将控件 ID 的顺序及显隐保存在既有 UI 偏好中，不清空接收数据或改变协议状态。发送 ASCII / HEX 使用分段滑块，切换时按 UTF-8 转换草稿；非法 HEX 或不能解码的二进制保持原稿并警告。定时发送用同一个按钮及绿色运行状态表达启停；发送历史使用回转时钟图标。

提示由驱动前端直接引用共享前端的 [非模态提示组件](../../apps/shared/docs/toasts.md)，错误红色、警告黄色，自动消失，不抢焦点；不新增 `DriverAPI` 或 MCP 工具，也不引入宿主权限或跨进程消息类型。

接收换行补全由配置面板的「LF 补 CR」「CR 补 LF」两个独立复选框控制，可同时勾选，默认均不选。分别将单独 LF、CR 补成 CRLF，已存在的 CRLF（包括跨事件拆分的 CR / LF）不重复补全。该功能只作用于终端和 UART 文本显示；终端对后续输出生效，UART 文本从有界原始缓存重新渲染。HEX、保存文件、收发计数、后端缓冲与 MCP 输出保持原样。清空、连接更换和回放缺口均重置转换状态。

显示偏好按宿主提供的 `api.instanceConfigRef`（工作区固定 `configRef`）保存在前端本地存储，包含终端 / UART 视图、接收 ASCII / HEX、时间戳、自动滚动、两项换行补全和退格编码。不使用 COM 口、实例名称或每次恢复都会变化的运行 ID 作跨启动主键；同一 COM 口的不同保存项相互隔离，恢复原保存项可找回设置。挂载时先恢复显示偏好，再订阅和回放；不保存发送草稿、历史或定时发送状态。旧宿主缺少固定标识时仅保持运行实例内偏好；旧换行设置只从已知当前运行 ID 迁移，无法安全归属的历史键不猜测迁移。

串口终端的普通 Backspace 默认通过 `serial.write` 原样发送一个 BS（`0x08`），配置可切换为 DEL（`0x7F`），不追加行结束符，由设备负责回显 / 编辑。仅拦截终端输入区无修饰键、非输入法组合的物理 Backspace；粘贴、API 控制字符及 UART / 配置输入框保持原有语义，不在本地伪造删除。

UART 发送行尾 `none/cr/lf/crlf` 随实例 `configRef` 保存，挂载时恢复，旧偏好缺少该字段时默认 CRLF；不改变终端原始按键或 MCP 命令的默认行尾。发送 ASCII / HEX、定时发送间隔和运行开关不持久化，恢复偏好不触发发送。

文件导入使用用户选择的浏览器 File，只导入草稿，确认后发送；ASCII 按 UTF-8 读取，HEX 导入原始字节。接收保存是有界缓冲的快照下载，不开放任意路径文件代理。发送历史只驻留当前挂载内存，最近 50 项且总计最多 64 KiB，失败不录入。定时发送默认 100 ms、范围 20–60000 ms，等待上次完成再计时；改稿、切换视图、断线、失败或卸载后停止，不恢复旧队列。实现进度与限制见 [Serial 进度](../../drivers/driver-serial/docs/progress.md)。
