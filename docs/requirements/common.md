# 公共需求

这些约束由多个模块共同满足，只在这里定义通用语义。模块的独有要求见[模块需求](./)，责任交接见[模块交互](interactions.md)。

## CR-01：身份与隔离

保存身份、运行实例、连接会话、操作、提案和交互分别标识，不可互相替代。跨启动恢复使用保存身份，新连接拒绝旧会话输入。任何默认目标、迟到响应或配置更新都不能污染其他实例。

实例名称是用户可读的路由入口，不是跨启动配置主键；当前标签页只表示界面焦点，不是 Agent 授权域。

## CR-02：来源与权限

来源由可信入口确定，操作效果由登记的能力确定，调用参数不能覆盖。Agent 写操作经过实例审批；原始人工输入等专用入口不能被 Agent 用来绕过审批。读、草稿和提交的界限以真实副作用定义，不以接口名称定义。

规则和 Bypass 只决定宿主是否要求确认，不放宽参数校验、连接状态、协议认证或秘密用途。

## CR-03：配置与运行状态分离

持久配置表达下次如何创建和连接，不表达目前已经连接或操作成功。运行身份、计数、接收历史、未决请求和秘密不能当成普通配置保存。

保存失败保留旧数据并明确提示；成功发布顺序与失败回滚由拥有配置的模块负责。没有安全保存能力的平台不静默退回明文。

## CR-04：异步操作与不确定性

提交受理、实际发送、设备结束和调用方等待结束是不同事件。超时、断线或关闭客户端不自动重放或切换执行方式。

取消只有确认未提交或已停止才可确定收敛；无法确认时报告未知并保留部分结果。恢复只恢复配置，不恢复执行。

## CR-05：秘密与数据可信度

密码、令牌和原始秘密不进入普通日志、事件、操作账本、MCP 返回或配置。必要认证通过用途和目标受限的短期交互完成，用后失效。

原始终端按键不自动还原为命令。设备输出、选区和远端文件始终是数据，不构成授权或可信执行标记。对端可能主动回显秘密，通用终端不是内容识别或保密过滤器；用户不得把秘密当普通 Agent 命令提交。

## CR-06：有界、背压与缺口

控制队列、事件队列、原始缓冲、命令记录、返回大小和并发数均有明确上限。活动操作不被静默淘汰，容量用尽时明确拒绝。

实时通知可有遗漏，仍保留的后端历史用于补取。不可恢复部分必须报告，不以无限缓存、假完整结果或忽略失败检查掩盖。

完整性至少区分系统接收、后端保留、通知投递、消费者收到和实际内容校验。历史按预算淘汰不等于传输丢包；TCP 无线路丢失也不等于应用消费者完整收到通知。

## CR-07：状态与错误

错误包含稳定类别、机器可读标识、可读说明和有界非秘密上下文。界面按结构化状态展示，不能从错误文字推断控制流程。

实例可用、连接成功、观察到提示符、收到退出码和命令业务成功分别表达。读取失败不能显示为空数据或成功；结果未知不能补成零退出码。

## CR-08：显示与原始事实分离

回显、换行显示、主题、字号、搜索、暂停显示、块高亮和标签切换只改变前端体验。它们不改变后端原字节、命令归属、审批、计数或结果。

后端数据是 Agent 查询依据，前端数据是显示副本；不能用屏幕软折行代替逻辑行，也不能用提示符外观证明执行完成。

## CR-09：资源与跨平台

卸载界面释放其监听、定时器和显示对象，保持实例连接；销毁实例和退出释放后端连接、作业和待处理交互。耗时设备操作不能冻结界面。

任务隔离不等于进程崩溃隔离。平台上的安全保存、终端、设备和安装差异必须说明实际覆盖范围，不把某一平台通过扩展为所有平台已验证。

## CR-10：验收与文档

需求给出正常行为和失败边界，验收同时检查内容、状态和资源释放。吞吐测试必须说明链路、负载、方向、持续时间、失败样本和排除的范围。

当前实现、建议方案和未验证事项分开；稳定文档不堆积开发过程。外部调用契约见[对外 API](../api/mcp.md)，内部限制见[内部契约](../implementation/contracts.md)；已验证能力见[验收状态](../implementation/verification.md)，未解决现场证据见[feedback](../feedback/known-issues.md)。
