# 审批与交互需求

## 职责与配置

审批决定某次提交是否需要用户决策，交互取得认证、确认和选择等必要响应。模块不执行命令，也不把规则匹配当作协议认证。

规则组包含稳定身份、名称、拦截方式和规则列表。组可以不绑定实例，也可以被多个不同驱动的实例引用。每个实例最多绑定一个规则组，并拥有自己的 Bypass。

| 编号 | 要求 | 验收条件 |
|---|---|---|
| AP-01 | 每个运行实例独立判断审批 | 相同驱动的两个实例可以绑定不同组、具有不同 Bypass |
| AP-02 | Agent 的写入或状态变更默认要求审批 | 未绑定组且 Bypass 关闭时必须审批；已绑定组按该组模式判断 |
| AP-03 | 支持正向放行与反向拦截 | 正向命中免审批，否则审批；反向命中审批，否则免审批 |
| AP-04 | 数组按原始每项匹配，多行作为整项 | 正向要求每项均命中；反向任一项命中则整个提交等待审批 |
| AP-05 | 规则只检查明确声明的命令文本 | 文件内容、原始按键、连接参数、缺失或格式错误的字段不能套用命令规则豁免 |
| AP-06 | 组保存后对全部绑定实例的新提交立即生效 | 已等待审批的提案保持待决，不自动执行 |
| AP-07 | Bypass 由用户主动开启，仅影响当前实例审批 | Agent 不能修改；不能跳过参数校验、认证或密码交互 |
| AP-08 | 用户查看、编辑、批准或拒绝完整提案 | 批准绑定本次参数快照、实例和连接；目标变化后拒绝旧提案 |
| AP-09 | 规则与绑定明确保存，失败保留草稿和旧策略 | 无效规则、冲突名称、容量超限和写盘失败均不部分发布 |
| AP-10 | 有绑定的组不能直接删除 | 先取消绑定或改绑；复制组只复制规则，不复制实例绑定 |
| AP-11 | 秘密交互独立于普通审批和操作记录 | Agent、日志和普通事件不能取得原始秘密或一次性引用 |
| AP-12 | 取消、过期、实例销毁后拒绝迟到交互 | 旧弹窗结果不能替新交互提交响应 |

反向模式的空规则会让参与文本匹配的命令全部免审批。界面必须明确展示这一结果，不能用“未配置规则”掩盖它。规则匹配是文本匹配，不解释 Shell 语法、别名或被调用脚本，不能承诺等同安全命令分析。

## 界面需求

- 应用设置提供独立规则组管理：搜索、创建、复制、命名、模式、增删规则、试匹配和保存；没有实例也能使用。
- 组列表标明是否被引用，保存前可见受影响实例。宽窗口列表与编辑器并列，窄窗口在列表与详情间切换。
- 实例入口只选择一个组或未分配、查看规则和切换 Bypass；需要编辑组时进入同一管理界面。
- Bypass 与规则摘要分开显示，不能在 Bypass 生效时把试匹配结果当作本次实际审批结论。
- 离开未保存草稿提供保存、放弃和继续编辑。试匹配不执行设备操作。
- 待审批和认证请求集中可见；读取状态失败保留上一份内容并提示，不伪装成全部处理完毕。

## 保存与秘密边界

组目录独立保存，实例保存引用和自身 Bypass；已保存实例重启恢复，临时实例不落盘。组更新、复制和改绑不改变 Bypass，细表见[工作区与配置](workspace.md)。

原始秘密只交给指定实例的认证用途，短期、一次性使用。认证失败不得无限重试；通用多轮认证和多因素认证不作为已经具备的能力。

驱动级写操作不借用某个实例的规则或 Bypass。人工操作与 Agent 操作的来源必须由可信入口确定，不能由调用参数自报。

公共约束见[来源、秘密与异步状态](common.md)；批准与秘密交接见[模块交互](interactions.md)。
