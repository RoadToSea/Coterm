# 数据记录与读取需求

## 职责与数据分层

本模块是一组数据责任，不要求把所有协议数据集中到同一个存储对象。操作账本保存宿主执行摘要，驱动保存设备正文与命令归属，前端保存显示副本。

| 数据 | 用途 | 权威方 |
|---|---|---|
| 操作账本 | 来源、目标、审批状态、执行状态和脱敏结果摘要 | 实例运行 |
| 接收历史 | 真实收到的字节、文本及独立错误流 | 对应连接驱动 |
| 命令记录／对话 | 批准的输入、所属输出、完成证据和截断信息 | 对应连接驱动 |
| 选中文本快照 | 用户明确授予 Agent 的选区上下文 | 后端保存，人工界面更新 |
| 显示副本 | 滚动、搜索、块样式和本地显示转换 | 前端，仅对显示负责 |

## 需求

| 编号 | 要求 | 验收条件 |
|---|---|---|
| DATA-01 | 接收数据后端与前端分别保留有界副本 | 关闭视图后后端仍可查询，重新打开可恢复仍保留的内容 |
| DATA-02 | Agent 查询后端，不依赖界面是否可见 | 切换标签或关闭面板不改变命令结果归属 |
| DATA-03 | 提供最近若干行读取，无消费游标 | 重复读取可返回相同内容；行指逻辑换行，不是屏幕折行 |
| DATA-04 | 支持的 Shell 提供人工选区读取 | 没有选择返回空文本；Agent 不能伪造选择；过期连接选区清除 |
| DATA-05 | 支持的 Shell 提供最近若干对话读取 | 默认最近两条，按新到旧；运行中可返回部分结果 |
| DATA-06 | 字节流拒绝对话与 Shell 选区读取 | 能力查询明确标示，不通过空对话伪装支持 |
| DATA-07 | 输入、普通输出、错误输出的键始终保留 | 无内容为空；未知退出码和错误状态不填假值 |
| DATA-08 | 独立流与合并流如实标示 | 不能区分时合并到普通输出，错误流为空；不按关键词拆分 |
| DATA-09 | 可靠边界与观察边界分开 | 提示符、人工观察和异步日志不能被当成可靠退出证明 |
| DATA-10 | 所有历史、单条正文、返回结果有界 | 淘汰、预算裁剪和传输缺口分别可见；运行中记录不能静默淘汰 |
| DATA-11 | 读取失败不回退到另一个目标或操作 | 指定操作不存在或已淘汰时明确报错 |
| DATA-12 | 数据不默认持久化为长期日志 | 退出或销毁后不承诺恢复正文，配置恢复不恢复历史 |

## 对话与批次

“一对”表示一个已确定输入单元及其结果，不要求所有驱动内部产生相同边界：

- SSH 和 Local 当前一次命令提交形成一条记录；命令数组批次属于同一条输入，不伪造逐项输出归属。
- Serial、Telnet、Raw TCP 的 Shell 模式逐条发送并等待提示符，因此每个列表项可以形成一对。
- 人工输入只有在已有可靠上下文或明确观察证据时才可记录；原始按键不得直接重建为命令，尤其不能把密码输入归入普通记录。
- 提示符观察到的完成、可靠退出、运行中和结果未知必须可以区分；设备出现提示符不等于退出码为零。

最近两对读取返回的是该驱动定义的最近两个输入单元，不保证等于最近两次工具调用。若以后要统一批次粒度，应先确认需求再改接口。

## 数据保真与缺口

- 后端原始数据保留字节事实；文本解码可替换非法编码，但必须保留获取原字节的内部路径。
- ANSI 处理、逻辑行读取和屏幕显示不是同一种数据。不同驱动的行读取是否保留控制序列在接口参考中明确，不声称统一屏幕重建。
- 内部显示回放可用连接内位置，但 Agent 不维护位置。
- 实时通知缺失可尝试用后端仍保留的历史恢复；超过保留范围后明确报告缺口，不能承诺任意慢消费者无损。
- 接收计数、通知消费计数、实际内容校验分别统计。计数相等不证明内容无损，设备错误计数为零也不证明线路无损。
- 断开可保留当前快照；重新连接、通信参数重配和销毁的保留规则由驱动明确。任何时候不得将旧连接的数据误归为新连接输出。
