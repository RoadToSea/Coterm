# 第一阶段：基础闭环

本阶段的目标是验证 Coterm 的最小插件闭环：一个协议插件的后端、可选前端、用户交互和原生 MCP 能力由同一个插件实例关联起来，基座只提供运行时、界面挂载、公共交互和单一 MCP Bridge。阶段方案必须覆盖无 UI 插件和同一插件的多个并行实例。

截至 2026-10-26，SSH 已是基础闭环的参考协议，串口已有第二种协议初版。当前处于阶段收尾，不能把已有代码等同于全部验收通过。跨分支进度与缺口见[项目进度评估](../../PROGRESS.md)。

## 交付与验收矩阵

| 验收项 | 当前证据 | 剩余验收 |
|---|---|---|
| 插件发现、生命周期、多实例 | 插件运行时与真实子进程测试；坏包诊断、实例绑定已实现 | 安装包内发现、崩溃恢复、退出与资源回收 |
| 插件自有界面及无 UI 形态 | SSH/串口独立前端；本地插件无前端骨架 | 无 UI 插件请求公共交互的完整桌面场景 |
| SSH 与 MCP 共享实例 | 本地测试 SSH 服务、真实插件进程、HTTP/stdio 集成测试 | Windows/macOS/Linux 桌面与远程服务器验收 |
| Agent 提案、人工修改/拒绝、Bypass | 操作路由及秘密输入回归测试 | 真实桌面多实例并发与异常断开验收 |
| 界面订阅与秘密交互竞争 | WS-13 真实组件 + 浏览器 + 可控 IPC 测试 | 与真实 Tauri 事件的联合端到端验收 |
| 有界输出与缺口处理 | SSH/串口回放缓冲、JSON 事件和消费确认 | 长时压力、慢消费者、持续订阅型插件；二进制流属下一阶段 |
| 串口第二协议 | 领域/基座加载测试；历史 CH340 实机记录 | 读取线程退出、输入脱敏、Unix 设备路径、当前硬件复验 |
| 开发与发布 | Rust 工作区及前端构建脚本 | CI、锁文件、全平台插件包与 Tauri 安装包 |

阶段完成条件：上述基础路径有可复跑证据，失败与取消不伪装成功，无 UI/多实例路径可用，且发布目标平台没有已知阻断问题。插件市场、协议扩展、完整二进制流及 MCP Resources/Prompts 不作为第一阶段已交付能力。

插件作者可先阅读 [插件开发者指南](../../architecture/plugin-development.md)。本阶段的接入规范冻结与验证应覆盖指南中的生命周期、并发、交互、流控和多实例验收要求；指南中的示例目前不是已发布 SDK。
