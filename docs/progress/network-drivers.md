# 网络驱动进度

## 当前能力

- Telnet 与 Raw TCP 作为进程内驱动随桌面分发，支持独立多实例、显式连接、超时、可选自动重连及无认证 SOCKS5／HTTP CONNECT 代理。
- Telnet 支持增量 IAC、NVT、BINARY／ECHO／SGA／NAWS／TTYPE 协商与可选用户名预填。密码由人工终端输入，不保存到连接配置。
- Raw TCP 共享串口的终端／字节工作台，支持文本与任意字节 HEX 收发；终端／字节视图对应 Shell／stream 解释模式。
- 两个驱动使用现有实例审批、配置保存与 MCP 路由。Shell 提供三类无游标读取，stream 只提供 read_lines；后端有界保存接收数据和对话，前端保留显示副本。
- 重连创建新 connectionId，拒绝旧输入及旧审批提案，不重放命令。前端每 2 秒补取状态与遗漏回放，卸载清理订阅和定时器。

## 2026-11-11：输出批次与前端追赶修复

- 旧 4 KiB socket 读取在生产 DriverTask 链路中复现通知过载：3 秒无节流，后端接收 543,178,752 字节，消费少 1,396,736 字节，广播跳过 341 个事件。改为每次最多 64 KiB 读取，不扩大队列；相同入口复测接收 519,258,112 字节，内容完整，广播缺口 0。
- 前端原先把每个事件固定视为一个回放块，大事件被误判为缺口，转入逐页 1 KiB RPC。现按 ceil(bytes / 1024) 判断连续性；两个网络驱动的浏览器回归覆盖连续多块不回放、真实缺口补读和重复通知不重复呈现。
- 双向压测原本把投放生成器放在同一个任务，持续就绪的接收生产者压低发送投放。改为独立 Tokio 任务，保留 socket 到两个方向均完成后再关闭。两次无节流短对照，原 TX 约 1.94–1.96 MB/s，分任务后约 44.26–45.46 MB/s；这是校正压测调度，不是产品平白增加同等倍率吞吐。重复短测也曾检出广播遗漏并非零退出，无节流不承诺任意调度下无损。
- 最终 release 示例经生产 DriverTask 同时收发，五档各 60 秒。每方向实际吞吐和完整性如下，MB/s 使用十进制；不包含完整 Runtime、WebView、xterm、MCP 或审批：

| 每方向投放目标 | RX MB/s | TX MB/s | 实际内容 | 广播缺口 |
|---|---:|---:|---|---:|
| 5 MiB/s | 5.24 | 5.24 | 双向完整 | 0 |
| 10 MiB/s | 10.48 | 10.48 | 双向完整 | 0 |
| 50 MiB/s | 52.43 | 42.93 | 双向完整 | 0 |
| 100 MiB/s | 104.85 | 39.07 | 双向完整 | 0 |
| 不主动限速 | 134.15 | 37.29 | 未通过 | 27 |

- 四档限速实际内容完整，广播缺口 0。无节流时 RX 约 134.15 MB/s、TX 约 37.29 MB/s，RX 消费少 1,132,928 字节、广播跳过 27 个事件，整组按非零退出，不能称为无损容量。高 RX 下 TX 仍未达到同速投放目标，接收值也不代表双向同速、远端 Telnet 或桌面渲染上限。接收侧每次主动让出调度的短对照无稳定收益，未保留该改动。
- 有界历史仍正常淘汰，各档 replayGap／readLinesDropped 均为 true。主动慢消费负例：5 MiB/s、3 秒、暂停 1500 ms，后端计数完整，消费少 6,539,000 字节，广播跳过 295 个事件，按预期非零退出。没有把任意慢消费者改造成无限缓存的无损通道。
- 工作区 check、Rust 回归、严格 Clippy、五驱动前端及桌面前端构建、105 项前端回归通过；示例 2 项 Rust 校验器与 2 项 Node 校验器测试通过。入口：[生产队列示例](../../crates/coterm-driver/examples/tcp-task-throughput.rs)、[浏览器回归](../../tests/network-drivers-browser.test.mjs)、[容量与游标约定](../architecture/network-drivers.md#连接缓冲与故障)。

## 2026-11-11：驱动接入与公共工作台抽取

- 后端新增 `tcp`／`telnet` 入口，`network` 共享 TCP 生命周期，`stream` 从串口提取接收缓冲、输入编码和提示符观察；无新增 Rust 依赖或宿主接口变更。
- 前端提取公共 xterm 生命周期与终端／字节工作台。SSH 保留命令块和后台作业，Serial 保留实际 UART 设置；Telnet 隐藏字节面板，网络表单不包含串口控制线或 SSH exec 参数。
- 网络命令提案向待审批内存提供完整 operation／args 草稿，批准时重新校验实例、配置版本与连接 ID。普通账本仍由宿主脱敏；Shell 超时和取消保留有界部分结果，并以未知结果收敛，不自动补发。
- 驱动测试覆盖任意字节和 UTF-8 拆包、多实例、审批前不发送、完整草稿、旧提案失效、批次超时／取消、重连不重放、慢消费者与缓存缺口、Telnet 协商、代理握手分片与目标首包。
- Windows 原生 WebView2 → MCP Stdio → 人工审批界面 → 两种网络驱动 → 本机回环 Shell 验收通过；验证后端对话读取、保存配置恢复及恢复后不自动连接。原有 Local PowerShell 原生验收保留并通过。
- 浏览器覆盖显式连接、配置校验与保存失败重试、连接 ID、Telnet 回显／Enter／退格、Raw TCP HEX、事件缺失时状态补取、窄屏及卸载清理。
- 最终验证：工作区全目标 check、274 项 Rust 测试（3 项真实串口硬件用例按原设置忽略）、全目标严格 Clippy 通过；五驱动前端、桌面及普通 debug EXE 构建通过。串行前端全量 103 项全部通过、无跳过；配置、HEX 和 360px 窄窗口截图已复核。

## 2026-11-11：持续吞吐与完整性验收

- 环境：Windows 11（10.0.26200）、Ryzen 7 5800H（8 核／16 线程）、32 GiB 内存、Rust 1.97.0、Node 22.22.2，release 构建，本机 TCP 回环。结果只适用于本轮负载和消费者，不代表跨平台或通用吞吐上限。
- 主验收直接使用生产 `DriverTask`：请求队列 64、驱动通知队列 128、广播队列 64；不经过 stdio，也不包含完整 Runtime 账本、WebView、xterm、MCP 或审批。双向同时传输带序号的 16 KiB ASCII 记录，逐字节比对，单独统计后端计数、缺失／重复／异常记录与广播缺口。

| 每方向投放速率 | 持续时间 | 后端接收／发送字节 | 内容校验与消费结果 |
|---|---|---|---|
| 5 MiB/s | 60 秒 | 各 314,556,416 | 双向完整，广播缺口 0 |
| 10 MiB/s | 60 秒 | 各 629,112,832 | 双向完整，广播缺口 0 |
| 不主动限速 | 60 秒 | RX 7,816,626,176；TX 91,045,888 | 后端计数完整、TX 完整；RX 消费少 23,078,892 字节，广播跳过 5,635 个事件 |

- 无节流时接收约 130.28 MB/s、发送约 1.52 MB/s，不是双向无损容量；消费端异常记录可由缺失事件切断帧造成，不能据此断定 TCP 线路比特损坏。三档历史均发生正常有界淘汰，`replayGap/readLinesDropped` 为 true；实时消费完整与历史无限保存是两个不同条件。
- 主动慢消费对照：5 MiB/s、3 秒，消费端暂停 500 ms，后端计数完整，RX 消费少 2,322,432 字节，广播跳过 567 个事件。程序按预期返回非零，证明能识别通知丢失，不能把后端计数相等当成无损证明。
- 额外诊断 JSON/stdout 路径各档 60 秒：1 MiB/s 和 10 MiB/s 双向校验通过；5 MiB/s 后端计数完整，但 RX 通知少 122,880 字节。结果非单调，反映该诊断消费者的调度影响，不据此给出 5 MiB/s 的产品上限。修正测试生产者每 16 帧让出一次 IO 后，5 秒无节流复测仍出现通知过载；接收约 73.55 MB/s、发送约 4.70 MB/s，TX 完整、RX 不完整。
- 复测入口：[生产队列示例](../../crates/coterm-driver/examples/tcp-task-throughput.rs)、[诊断脚本](../../scripts/benchmark-tcp.mjs)、[校验器测试](../../tests/throughput-frames.test.mjs)。任一完整性失败均返回非零，过载场景亦然；命令与覆盖边界见[网络驱动架构](../architecture/network-drivers.md#性能与完整性测试)。

## 限制与续作入口

- Telnet 与 Raw TCP 均无 TLS；代理仅支持无认证模式，未实现代理账户或通用登录脚本。
- Telnet 仅响应服务端发起的受支持选项协商，不宣称完整 RFC 1143 状态机或所有设备兼容。
- Shell 以完整字面提示符观察边界，忽略末尾空白；提示符不证明执行成功，exitCode 为 null，stderr 无独立通道时为空。人工登录后必须先收到 Shell 提示符。
- stream／HEX 命令仅确认发送，未捕获设备完成结果；接收数据用 read_lines 查询。接收数据、计数、历史与连接状态不跨启动保存。
- 本轮验收使用 Windows 回环服务端和协议夹具，未使用真实远程 Telnet 设备、实际代理部署或 Linux／macOS 实机；发行安装包另行验收。
