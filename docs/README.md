# Coterm 文档

Coterm 面向人类与 Agent 协同操作终端和连接设备，支持 SSH、串口、本地终端、Telnet 与 Raw TCP。非标设备协议解码、连续波形和信号数学分析不属于本项目范围。

## 阅读顺序

| 顺序 | 文档 | 回答的问题 |
|---|---|---|
| 1 | [模块架构](01-modules.md) | 项目分成哪些模块，为什么这样分 |
| 2 | [模块需求](02-requirements/) | 每个模块必须完成什么，如何验收 |
| 3 | [公共需求](03-common-requirements.md) | 哪些约束需要全项目共同遵守 |
| 4 | [模块职责与信息交互](04-module-interactions.md) | 数据归谁管理，模块之间传递什么，失败怎样处理 |
| 5 | [代码架构](05-code-architecture.md) | 先确定整体依赖，再复用公共能力，最后安排模块内部实现 |

第 1–4 步定义业务模块、需求和信息语义，不规定编程语言、类、目录或消息编码。第 5 步将这些要求映射到当前代码，并单独标明后续建议。逻辑模块不等于独立软件包，也不要求每层增加一次转发。

模块需求按职责阅读：

- [工作区与配置](02-requirements/workspace.md)：保存、恢复和配置范围。
- [实例运行](02-requirements/runtime.md)：实例、连接、操作和退出。
- [审批与交互](02-requirements/approval.md)：规则组、实例策略和秘密交互。
- [通信驱动](02-requirements/drivers.md)：五种连接的配置、行为和能力差异。
- [数据记录与读取](02-requirements/data.md)：后端数据、对话、选区和读取。
- [桌面交互](02-requirements/desktop.md)：工作区、终端、字节调试与公共操作。
- [Agent 接入](02-requirements/agent.md)：工具发现、目标路由和异步结果。

## 维护方式

- 每项稳定要求只在所属需求文件定义；公共要求集中维护，交互文档只描述数据责任与交接。
- 实现说明放在代码架构和接口参考，不倒灌到需求文件。变更业务行为时先核对需求，再同步交互与实现说明。
- 状态文件只保留当前有效结论、必要验收证据和未解决问题；开发过程、逐次修改记录交给 Git。
- 长文档统一放在本目录。模块源码旁保留必要的接口注释和示例，不再各自维护一套需求、架构、用法和进度文档。
- 新增依赖、持久化结构或共享基础接口的实现变更仍需单独确认；整理文档不视为授权修改这些实现。
