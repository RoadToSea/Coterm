# 终端聚焦与内置驱动架构设计

## 目标与定位

Coterm 专注于面向人类与 Agent 协同的**纯终端类交互基座**，核心支持 SSH、串口终端（Serial）以及本地终端（Local Terminal）。

系统明确业务边界：**放弃对底层非标字节流解码、流式波形分析和信号数学计算的扩展**。底层连续信号采集、多通道波形分析、CAN 负载监测与协议逆向等场景划归专用虚拟仪器上位机（如 Lissio）。Coterm 全面收敛并专精于字符流、ANSI 终端渲染、命令块交互与 Agent 写操作审批治理。

## 核心架构原则

1. **开箱即用，消除驱动感知（In-Tree Drivers）**：
   - 核心终端协议（SSH、Serial、Local）作为第一方内置驱动随应用直接分发；
   - 彻底废除面向普通用户的“驱动市场”、“离线驱动包（.coterm）安装”、“驱动运行时验证”等外置管理机制；
   - 用户打开应用即可直接选择“新建 SSH 会话”或“新建串口会话”，实现秒级冷启动与即开即用。

2. **坚守进程级故障隔离（Fault Isolation Under the Hood）**：
   - 产品交互体验上实现“全内置”，但底层驱动运行时依然保持**轻量级独立子进程（Worker）**架构；
   - 宿主进程（`coterm-desktop`）通过本地轻量 IPC 按需调度各驱动 Worker；
   - USB 串口硬件意外拔插、Win32 串口底层系统调用挂起、SSH 断线或驱动层异常 Panic 均被严格限制在子进程内部，绝不击穿桌面宿主，保障多实例并发与其他生产会话零闪退。

3. **专精终端与 Agent 协同体验**：
   - **终端字符渲染**：优化 xterm.js 与 PTY 缓冲区，抵抗串口海量高频日志冲击，避免内存泄漏；
   - **命令块（Command Blocks）**：以块状结构捕获指令输入、标准输出、退出码与执行耗时，支持折叠与回放；
   - **人机权限仲裁**：保留 MCP Bridge 与命令审批拦截体系，Agent 提交写操作（`effect: commit`）默认经过人工确认或命中用户配置的正则白名单规则，杜绝向物理终端注入毁灭性指令。
   - **速度与安全的取舍**：对于接收的数据，没有锁以及审批机制。只对输入的命令有。因为终端通信的一个特点是输出和输入的不对称性，接收大量数据后只会发送一条命令，串口调试输出同理。

## 模块分工与拓扑

```text
┌────────────────────────────────────────────────────────────┐
│                    Coterm 桌面基座 (Host)                  │
│   Tauri v2 + React 界面                                    │
│   - 会话与实例标签管理 (Instance Tabs)                      │
│   - 人机操作审批与安全审计账本 (Approval & Ledger)          │
│   - 单一 MCP Stdio Bridge 转发网关                         │
└────────────────────────────────────────────────────────────┘
                              │
          ┌───────────────────┼───────────────────┐
          │ (本地 stdio IPC)   │ (本地 stdio IPC)  │ (本地 stdio IPC)
          ▼                   ▼                   ▼
┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐
│  内置 SSH 驱动   │ │ 内置 串口 驱动   │ │ 内置 本地终端   │
│  (In-Tree Worker)│ │ (In-Tree Worker) │ │ (In-Tree Worker) │
│  - russh / PTY   │ │ - serialport     │ │ - winpty/portable│
│  - 密钥与会话管理│ │ - 串口流转控制   │ │ - 本地 Shell 交互│
└──────────────────┘ └──────────────────┘ └──────────────────┘
```

| 模块 | 交付形式 | 职责边界 |
| :--- | :--- | :--- |
| **桌面基座** | 原生桌面单体 | 实例路由、终端视图、快捷键、操作账本、命令审批面板、MCP Bridge 适配器 |
| **SSH 驱动** | 内置 Worker | SSH 连接握手、私钥鉴权、伪终端（PTY）分配与尺寸同步、数据加解密 |
| **串口驱动** | 内置 Worker | COM 端口枚举、流控配置、波特率调节、接收换行补齐、拔插状态监测 |
| **本地终端** | 内置 Worker | 本地 PowerShell / CMD / Bash 子进程生成与生命周期管理 |

## 接口与交互收敛

1. **设置与界面精简**：
   - 彻底移除“设置 → 驱动管理”页面及其相关 API（如 `prepare_driver_change`、`commit_driver_change`）；
   - 主界面侧边栏直接展示终端实例创建入口：SSH、串口、本地终端。
2. **MCP 工具保留与路由**：
   - MCP 命名空间保持规范收敛：`coterm_ssh_*`、`coterm_serial_*`、`coterm_local_*`；
   - 依然支持 Agent 通过 `coterm.list_instances` 查询当前活跃实例并定向发送命令块，写操作依然受基座规则引擎审计。
