# 审批规则组与实例分配

状态：实现前设计，尚未修改代码或持久化结构。已确定规则组独立存在、包含匹配方式与规则列表；每个实例最多绑定一个规则组，组保存后对所有绑定实例的新提交立即生效。界面布局与其他边界行为按下述方案设计。

## 数据归属

规则组属于用户配置，可在没有任何实例时创建，可同时供不同驱动的实例使用。删除或销毁实例不删除规则组；没有绑定实例的组是有效配置。

建议的数据形状：

```ts
type ApprovalRuleGroup = {
  id: string;
  name: string;
  mode: "allow_matches" | "approve_matches";
  patterns: string[];
};

type InstanceApprovalSettings = {
  approvalRuleGroupId: string | null;
  bypass: boolean;
};
```

`id` 是宿主生成的稳定标识，不随改名变化；`name` 用于选择与区分规则组，建议去除首尾空格后非空且不重名。`mode/patterns` 复用现有 `ApprovalPolicy` 的匹配语义与校验限制。实例绑定按已有 `configRef` 保存，运行实例 ID 只负责当前路由，不把规则正文复制到每个实例。

`bypass` 继续归实例所有，组编辑、复制、分配和取消分配都不修改它。已保存实例恢复原开关；临时实例不落盘。

建议在已有工作区文档中保存独立的 `approvalRuleGroups` 集合和每项的 `approvalRuleGroupId`，复用现有加密及原子替换，不另建数据库或存储框架。规则组集合不受「只保存当前会话实例」过滤影响，删除最后一个实例也必须保留未绑定的组。非 Windows 持久化限制沿用当前实现。

## 审批行为

| 状态 | 新的 Agent 提交 |
|---|---|
| 当前实例 Bypass 开启 | 跳过宿主审批，协议认证与参数校验仍执行 |
| Bypass 关闭、未绑定规则组 | 所有 commit 需要审批 |
| 绑定正向放行组 | 每个命令项均命中组内任一规则才免审批 |
| 绑定反向拦截组 | 任一命令项命中规则则整次提交需要审批，否则免审批 |
| 绑定不存在的组或规则无效 | 不获得规则豁免，报告配置异常 |

规则仍只适用于驱动明确声明的命令字段，未声明命令字段的写操作不因反向组而免审批。正向空组全部需要审批；反向空组会放行所有参与匹配的命令。界面直接显示这些结果，避免只用「正向／反向」表达含义。

组内规则是无顺序的正则列表，不增加逐条优先级、规则嵌套、独立启停或继承。不同驱动可引用同一组；具体能否匹配由驱动已有的命令字段契约决定。

## 绑定与共享更新

每实例一个可选组。不同环境可以绑定不同组；局部调整先复制组，再绑定新组。无需设计多个组的优先级、与／或关系或冲突解决。

多组叠加会产生「一组放行、一组拦截」的合并问题，因此本方案不提供多组选项，也不增加绑定顺序。

实例引用共享组：保存后，所有绑定实例的后续新提交使用新规则。保存按钮附近显示受影响实例名称；编辑草稿不影响实际审批，已等待审批的提案仍需原人工处理，不追溯放行，不重放操作。

模板复制方案可以避免共享更新，但会引入模板与实例副本不同步、界面显示组名却无法代表实际规则的问题。本方案采用引用绑定，复制操作仅用于创建一个新的独立组。

## 规则组管理界面

从应用设置进入「审批规则组」，复用现有原生对话框、主题和 React/shadcn 控件。管理页不依赖活动实例；从实例面板跳转编辑时切换同一对话框内容，并保留返回入口，避免多层模态窗口。

建议桌面管理页宽约 960px、上限为窗口宽度减 32px。左侧约 220px 为组列表，右侧编辑选中组；窄窗口改成列表与详情两级导航，不把两列硬挤进屏幕。

```text
审批规则组                                             关闭
──────────────────────────────────────────────────────────
搜索规则组…           │ 名称  [开发板日常命令            ]
                      │
开发板日常命令         │ 匹配方式
  正向放行 · 已分配    │ [命中免审批]   [命中需审批]
服务器维护             │ 未命中的命令需要人工审批
  反向拦截 · 已分配    │
升级前检查             │ 规则
  正向放行 · 未分配    │ ^pwd$                         删除
                      │ ^uname(?: -a)?$               删除
                      │ [输入正则表达式…           ] [添加]
                      │
                      │ 测试命令 [                       ]
                      │ [测试匹配]  需要人工审批
                      │
                      │ 使用此组：开发板、测试机
──────────────────────────────────────────────────────────
[新建规则组]          │ [复制] [删除]       [取消修改] [保存]
```

- 列表显示组名、匹配方式和「已分配／未分配」，不把未分配显示成错误或禁用状态。搜索只过滤列表，不自动改绑实例。
- 编辑器依次提供名称、匹配方式、规则列表和添加、命令测试、使用实例。模式按钮显示「命中免审批／命中需审批」，旁边显示未命中的实际行为。
- 复用当前命令测试入口，以编辑草稿测试，不执行命令。结果注明是组规则匹配结果，实例 Bypass 单独显示，不混为实际执行结果。
- 列表项用名称作为可见身份，内部 ID 不展示。规则允许直接编辑、删除和追加；逐项显示错误，保留失败草稿。
- 保存采用显式按钮。共享组已绑定时，按钮附近显示「保存后应用到：实例名称」，避免编辑者误以为只影响当前实例。
- 新建组默认正向放行、空规则；输入名称后可保存为空组，未分配也可保存。复制产生新 ID，名称待用户修改，不复制任何实例绑定。
- 已绑定组暂不允许删除，显示使用者，并引导先在实例中改绑或取消绑定；未绑定组删除不触碰实例。取消绑定的实际审批结果由实例的 Bypass 决定。
- 切换组、返回或关闭时有未保存修改，提供保存／放弃／继续编辑；保存失败保留编辑状态。加载失败可重试，初次空列表提供创建入口。

## 实例审批面板

当前实例的审批入口保留，但主要职责变成选择规则组及查看生效状态。已保存而未运行的实例也应能从实例菜单打开此面板，配置不应要求先建立连接。

```text
实例审批 · 开发板
────────────────────────────────────────────
规则组
[开发板日常命令                         ▾]
  未分配（所有命令需审批）
  开发板日常命令
  服务器维护

命中规则免审批；未命中需要人工审批
[查看规则]   [管理规则组]

Bypass：关闭
────────────────────────────────────────────
                              [取消] [保存]
```

规则正文以只读方式查看，编辑跳转到规则组管理页；不在实例面板另存一份独立规则。不提供额外的逐实例例外覆盖层。

「未分配（所有命令需审批）」是 Bypass 关闭时的说明。Bypass 开启时应显示「Bypass 已开启，当前跳过审批」，保留绑定但不让规则摘要误导用户。绑定数量、规则编辑等信息不伪装成连接状态。

## 保存与运行时数据流

| 现有模块 | 职责 |
|---|---|
| `ApprovalPolicy` | 整组规则校验、编译和匹配，不处理保存或实例分配 |
| `WorkspaceStore` | 保存规则组及实例引用，检查组名、引用和删除约束 |
| 宿主审批命令 | 路由人工配置操作，串联校验、持久化和运行时发布 |
| `ProcessDriverRuntime` / `InstanceApproval` | 对新提交使用当前组的规则；保持每实例 Bypass 独立 |
| 规则组管理页 / 实例面板 | 编辑组和选择绑定，不自行实现正则匹配或执行命令 |

```text
管理页草稿 → 宿主校验并编译 → 工作区原子保存
                                ↓
                   运行时发布新的规则组及绑定
                                ↓
                     实例审批对象处理新提交
```

共享规则组编辑先校验整组，再保存，再统一发布受影响实例的新规则；不按实例循环写盘，不允许部分实例换规则后才发现保存失败。实例审批对象仍独立拥有 Bypass；可复用不可变的编译结果，不共享可变实例状态。

实例创建、恢复与分配均通过宿主解析组引用；驱动及 MCP 不能编辑组或分配绑定。未运行的保存项更新后，下次恢复加载对应组。临时运行实例可在内存绑定已有组，但不因此创建持久化实例保存项。

编辑、绑定和删除在已有配置操作锁下检查引用并保存，避免「删除组」与「实例刚绑定」产生悬空引用。保存组和改变绑定只影响后续提交，不执行已有操作。

## 旧配置迁移

旧实例的独立规则迁移为独立组，并把原实例绑定到该组；已有默认正向空规则可表示为未分配。旧反向空规则必须保留其实际放行行为。

不因为两实例的规则内容相同就自动合并组，否则用户修改其中一个会意外影响另一个。组名称可以使用实例名称派生并消歧，稳定 ID 由宿主生成；原 `configRef`、Bypass、名称、分组与连接配置保持不变。工作区格式版本及旧接口替换随实现单独落实。

## 实施范围与验收

复用 [审批 matcher](../../crates/coterm-core/src/approval_policy.rs)、[工作区存储](../../apps/desktop/src-tauri/src/workspace.rs)、[审批界面](../../apps/desktop/src/components/host/ApprovalSettings.tsx) 和现有设置入口。不新增 crate、第三方运行时依赖或通用策略框架。

验收重点：无实例也能保存组；删完实例不丢组；同组多实例的更新一致；不同组与不同实例 Bypass 隔离；未绑定与空组行为明确；保存失败不改变生效配置；离线实例可分配；旧数据不被隐式合并；待审批提案不因组修改自动执行；窄窗口和键盘流程可用。
