# Coterm 架构规格

Coterm 面向软硬一体与边缘计算场景，让用户与 Agent 在同一连接实例中观察、输入、审批和中止操作。当前实现状态见 [项目进度](progress/project.md)。

## 核心原则

1. **基座最小化**：负责驱动生命周期、实例路由、前端挂载、公共交互、操作记录和 MCP Bridge。
2. **协议归驱动**：连接、领域模型、数据缓存、持久化、重连及原生 MCP 工具由驱动负责，不强制统一为终端或命令模型。
3. **共享实例**：界面与 MCP 使用同一驱动实例；不能根据当前标签页隐式选择 Agent 的操作目标。
4. **前后端经基座通信**：驱动前端使用绑定实例的 API，不直接访问后端进程、宿主内部状态或其他驱动。
5. **多实例与可选界面**：同一驱动可有多个实例；无 UI 驱动也能使用基座的公共交互。
6. **用户控制与安全审批**：Agent 写操作（`effect: commit`）默认经过人工审批；用户可独立维护正向放行或反向拦截规则组，每实例可选绑定一个组，保存组后对所有绑定实例的新提交生效；Bypass 只能由用户显式开启，不能绕过协议自身的认证。

## 组件关系

```text
外部 Agent → MCP Bridge ─┐
                        ├→ 操作路由 / 审批 / 账本 → 驱动后端 → 协议连接
桌面与驱动前端 → Host API ┘                           ↕
                        ← 公共交互 / 实例事件 ←────────┘
```

| 模块 | 职责 |
|---|---|
| 桌面基座 | 驱动发现/启停、实例与界面生命周期、公共交互、事件传递 |
| 驱动后端 | 协议连接、领域操作、数据管理与原生 MCP 能力 |
| 驱动前端 | 可选领域界面，通过基座 API 操作后端 |
| 通用 UI | 可选终端、块列表等呈现组件，不定义协议业务模型 |
| MCP Bridge | 单一入口、命名空间、工具发现、可信来源与路由，保留领域参数及结果 |

## 安全与可靠性

- 秘密通过受控交互传递，不进入普通事件、日志、MCP 结果或明文持久化。
- 高频数据必须有界，支持取消、慢消费者、断线与明确的数据缺口。
- 等待超时不等于取消；未确认提交或停止时报告结果未知，不自动重放写操作。
- 第一版前端在同一 WebView 中加载可信模块；进程隔离和 API 边界均不等于安全沙箱。
- 驱动入口使用包内相对路径，不提供任意 shell 或任意文件访问代理。
- 后端 JSON 控制契约与前端 SDK 固定为 v1.0；流和扩展交互独立演进，修改实现时同步更新契约和测试。
- Windows 首版以 DPAPI 保存工作区与配置引用，用户显式恢复实例；操作历史仅保留本次会话，恢复不重放写操作。

## 路线与入口

路线：基础闭环 → 稳定驱动运行时与跨平台交付 → 驱动信任、更新和生态；协议按驱动独立扩展。

驱动接入见 [开发指南](architecture/driver-development.md)，消息与交互见 [运行时通信](architecture/runtime-communication.md)，Agent 接入见 [MCP](architecture/mcp-integration.md)。具体优先级和验收缺口只在 [项目进度](progress/project.md) 维护。
